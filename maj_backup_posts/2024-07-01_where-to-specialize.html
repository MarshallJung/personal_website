Where to specialize

Everyone’s an expert right? Only about 18 months after the widespread publicity of GPT-3 and other foundational models the number of people with “AI Innovator” or other guru like title is thicker than a cat’s coat in winter. But for those that are just trying to understand how to best learn the tools today and apply them effectively to tasks, there is a way of understanding overarching capabilities and methods rather than specific technologies. Recommendations to “learn AI” have become much more nuanced after talking with and helping hundreds of people over the last year and a half. Most people shouldn’t:

  • Learn automations
  • Learn advanced prompting methods
  • Learn agent orchestration frameworks

These are rapidly changing, still unique to different providers and very likely to either change or more likely to disappear as the industry works towards consolidation. OTOH folks should:

  • Learn to think in systems and create process
  • Learn to delegate to AI systems
  • Learn to review and give feedback to AI
  • Learn to elevate themselves and work on designing the playbook, not doing it

Why? The first list of things is getting quickly commoditized, and tech will make it easier and easier. Look at the code assistant market for an example of how much the interaction and tooling has changed in the past two years. The second list is what makes the first bucket actually valuable, and is very transferable. As I’ve stated numeros times, I think there will emerge a specialized language that we use to interact with LLMs. This iterative and questioning language (“Socrato”) will help us form the systems and tests that are then carried out in grimbly details by the automated tools in the background.

Unstructured Data for RAG

https://neo4j.com/developer-blog/graphrag-ecosystem-tools/

Sure this a SaaS based service, but there will surely be some reasonably solid open source tools available. The KG Builder is a visual cloud service that easily turns unstructured data into a knowledge graph. You can point it to some random PDFs, a wikipedia page or a youtube video, and a few seconds later you have the data and concepts from those sources represented as a knowledge graph. As the idea of RAGs in enterprise environments fight it out for acceptance, the need for digesting, QCing and building more accurate data bases is key for performance. Any investment here is a solid ROI.

Drag and drop

Building AI workflows is pretty cool with existing tools. Check out this open source tool called Flowise: https://github.com/FlowiseAI/Flowise

Developing LLM apps often involves countless iterations. This low-code and drag-and-drop UI approach enables quick iterations, helping go from testing to production faster. Of course, “production” is always up for debate. It seems like this is an arena where Astronomer.io might be particularly well suited.

Security is still important

This is an important security event with a shady company muscling in a neglected but still used library to inject bad code for the purposes of exploiting those still using the older libraries. Those vulnerable companies are also likely the ones least well equipped to mange threats. What interests me is the increasing opportunity to exploit these older libraries using LLM coding tools to quickly refactor, inject and test old code. Not that this wasn’t happening before, but it will only be turbocharged.
